# Architecture atlas design

The approved cinematic direction extends the existing forest/lime identity. The architecture surface uses a deep forest ground (#0b1712), pale bone type (#eef1e8), lime (#c8f36a), mint (#80d9b0), apricot (#efb487) and periwinkle (#abb9ef). Body text stays high-contrast. Colour identifies domains and is paired with labels.

Self-host Manrope Variable for editorial headings and Instrument Sans Variable for reading. Body measure is bounded; technical strings can wrap. No external font requests, financial feed requests or tracking.

The signature interaction is a living system map: selecting a journey highlights the actual component path; selecting a component opens its input, output, trust and failure contract beside the map. It is an explanatory graph based on the MP blueprint, not live telemetry or a replacement for the canonical Lucid architecture.

The page progresses through a strong first viewport, a step-by-step import-to-outcome journey, system explorer, science and bounded research, cloud/network options, daily experience, operational controls and phase/source evidence. Vary section composition instead of repeating a card grid. Navigation, controls and integration rows remain familiar.

All movement is user-enabled. Framer Motion provides path/selection transitions; the lazy-loaded Remotion Player provides a deterministic captioned 72-second architecture story with controls, accompanied by the same transcript. Reduced motion disables ambient/path animation and offers the static transcript instead of the Player. There is no autoplay, narration service or cloud render.

This is a Read/Experience architecture surface, not the approved UX of the eventual app. Native Lucid exports remain the canonical technical drawings. At 390px the graph becomes selectable component rows with the same descriptions rather than shrinking labels beyond readability.
