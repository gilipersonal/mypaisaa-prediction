# Story readiness (MP-40)

**3 November 2026 · MP-40 · Planning only · No implementation authorised**

The owner signed off the architecture baseline at commit `98ba348` (MP-20). Its last gate before UX is CD-01: every
story has positive, negative and recovery acceptance, its data and authority contracts, a state inventory and its
dependencies, and is a real Jira story. This folder turns the 64 local drafts in the
[phase-story baseline](../ma-reconciliation-2026-11-02/phase-story-baseline.json) into those stories.

The owner chose (3 November 2026): **split the umbrella drafts into buildable stories**, and **create each phase's
stories in Jira as that phase is drafted**.

## The files

- `stories/PH-0N.json`: one file per phase. It holds the disposition of every draft in that phase and the stories.
- [`stories.py`](stories.py): the gate (`check`, `selftest`), the Jira description renderer (`body`), and the
  bookkeeping (`set-key`, `sync-trace`).

## What a ready story holds

```json
{
 "id": "PH01-S01",
 "jira_key": null,
 "phase": "PH-01",
 "epic": "MP-5",
 "title": "Owner-scoped accounts and listing identities",
 "story": "As the owner, I want ... so that ...",
 "from_drafts": ["L1-S01"],
 "acceptance": {
  "positive": ["at least two specific, testable criteria"],
  "negative": ["at least one thing that must be refused or must not happen"],
  "recovery": ["what happens after a failure, retry, restart or partial write"]
 },
 "contracts": [{"name": "ScopeEnvelope", "role": "reads"}],
 "authority": "Who may do what, and what is refused (owner, a code worker, a Claude route, nobody).",
 "states": ["at least three states the data or screen can be in, failure and staleness included"],
 "depends_on": {"stories": ["PH01-S15"], "gaps": ["PL-08"], "owner_questions": ["FIN-OD-01"], "external": ["PH-02: sign-in and step-up"]},
 "blocked_on_owner": true,
 "evidence": ["the test or check that proves it done"]
}
```

`recovery` may be replaced by `"recovery_not_applicable": "<reason>"` for a story that writes nothing.

## The rules the gate enforces

- Every draft in the phase is `kept` (one story), `split` (several), `merged` (into a story that also covers other
  drafts) or `dropped` with a reason. A story lists the drafts it came from, and each draft lists its stories.
- Ids are local (`PH01-S01`), never shaped like a Jira key. `jira_key` stays `null` until the Jira issue exists.
- The epic is the phase's crosswalk epic (PH-00, PH-02: MP-4; PH-01, PH-03: MP-5; PH-04: MP-6; PH-05, PH-06: MP-7;
  PH-07: MP-8; PH-08, PH-09: MP-9).
- Contracts are named from the foundation schemas (`specified`) or the phase contract catalogues (`planned`); the gate
  says which.
- `gaps` are ids in the gap register. `owner_questions` are open ids (SCI-D, FIN-OD, DATA-DEC, COST-Q, ARC-06b-O);
  an answered one is refused, so cite the answer instead. `blocked_on_owner` is true exactly when a question is cited.
- Story dependencies resolve and form no cycle. A dependency on another phase's story, while that phase is still
  being drafted, goes in `external` as `PH-0N: <what is needed>`; a final pass links it to the story id.
- No em dash anywhere: MP's Jira text uses hyphens, colons or commas.

## Authority for the content

The owner's recorded answers win (the [decision log](../ma-reconciliation-2026-11-02/decision-log.md), the
[policy answers](../foundation-policy-discussion-2026-11-02.md), the [ARC-06b card](../claude-models-and-batching-2026-11-02.md)),
then the root documents (`README.md`, `ARCHITECTURE.md`, `TECH-STACK.md`), then the
[foundation pack](../foundation-specifications-2026-11-02/README.md), then the draft itself. A draft written before
an owner answer is updated to that answer, never copied as it was. MA concepts are reference only.
