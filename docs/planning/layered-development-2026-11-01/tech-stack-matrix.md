## 3. Compatibility facts checked against primary sources

- **SvelteKit 3 is available.** The [official announcement](https://svelte.dev/blog/sveltekit-3-is-here) is dated 1 October 2026; the [migration guide](https://svelte.dev/docs/kit/migrating-to-sveltekit-3) covers its breaking changes. No SvelteKit version is currently installed in this product. Select a compatible exact Svelte/Kit/Vite/Node/adapter set with a lock when the build is authorised; do not substitute historical Svelte 3 for SvelteKit 3.
- **Static and SSR differ.** [SvelteKit static adapter](https://svelte.dev/docs/kit/adapter-static) produces static files. Dynamic server logic needs another adapter/runtime; Cognito client sign-in alone does not create server-side SvelteKit sessions.
- **SSE is a constrained AWS integration.** [API Gateway](https://docs.aws.amazon.com/apigateway/latest/developerguide/response-transfer-mode.html) documents REST proxy response streaming and a 15-minute ceiling. [Lambda](https://docs.aws.amazon.com/lambda/latest/dg/configuration-response-streaming.html) documents Python custom runtime/Web Adapter requirements and billed continuation after disconnect. Region availability and the complete authenticated Python path still need validation.
- **Workflow runtime matters.** [Durable Functions’ supported runtimes](https://docs.aws.amazon.com/lambda/latest/dg/durable-supported-runtimes.html) include Python 3.13/3.14 at this check; the starter CI’s Python 3.12 is not sufficient evidence for that choice. Step Functions remains the external state-machine alternative; neither is activated or selected here.
- **Financial atomicity has real bounds.** [DynamoDB transactions](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_TransactWriteItems.html) have action/size/idempotency limits. A staged immutable import with consistent commit visibility or an explicit relational alternative needs proof before design approval.
- **Cognito features do not prove a complete recovery design.** [Authentication flows](https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-authentication-flow-methods.html) describe federation/passkeys; [federated linking](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools-identity-federation-consolidate-users.html) is a privileged identity operation. Validate tier, canonical local owner, linking, recovery and reauthentication as one flow; do not grant access on email equality.
- **Claude tool use is an application trust boundary.** The [official tool-use guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works) describes the model/client exchange. Here, tool allowlists, authority, idempotency, budgets and continuation are controlled by our server code. Official client SDK support is different from adopting Claude Agent SDK.
- **Costs are not instantaneous.** [Cost Explorer](https://docs.aws.amazon.com/cost-management/latest/userguide/ce-what-is.html) documents delayed updates and paid paginated queries. [Anthropic analytics](https://platform.claude.com/docs/en/manage-claude/usage-cost-analytics-api) is a historical organization report, not proof of the owner’s promotional balance. Permission/response/API version checks remain future implementation evidence.

These facts were checked on 1 November 2026 through official documentation/web or AWS MCP documentation tools. No AWS/Anthropic account calls or credential inspection were made. Target versions, quotas, pricing and regional support must be checked again at implementation; this draft makes no compatibility guarantee based only on a package name.

## 4. Ownership, contracts and launch gates

Environment is an immutable attribute on business/job/cost evidence. Dev and prod have separate write authority, stores, queues and client configurations; local uses prepared offline fixtures. Shared DNS/builds/organization credits are reported once under an agreed allocation or shared/unallocated view. Separate resources do not imply verified cost tags or separate credit pools.

Contract pack required before app build: owner/session claims and protected actions; instruments/FX/calendars; import manifest/preview/confirmation/commit visibility; ledger/precision/reversals; job/outbox/retry/cancel; event cursor/snapshot/reconnect; source/factor/feature lineage; model/forecast/mature outcome; conversation/tool/agent/evaluation manifests; cost reservation/report reconciliation; audit retention/deletion/restore; Swift/RN/web compatibility schemas. Put schema version and environment on durable envelopes and preserve backward compatibility through rolling client/backend upgrades.

The source requirements contain 140 captured MA stories mapped into Prediction capabilities; that inheritance is not permission to duplicate their old stack choices or call target functionality implemented. Future China/Taiwan/Hong Kong/continental Europe, theme expansion and model families require rights, evaluated compatibility, incremental cost and owner approval; the initial 20–30-instrument examples do not fund all future scope.

Minimum readiness evidence: end-to-end requirements and UX agreement; ADR conflict resolution and A/B choice; full-scope £70 operation/£30 reserve recost; source/layout/device identity gates; contract/invariant/error/recovery cases; security/access-isolation and package checks; quant leakage/calibration/ablation tests; web/native accessibility/reconnect/offline/push tests; budget exhaustion/ambiguous-call reconciliation; monthly restore/audit exercise design. Apply these with each layer, then run complete release gates. Current CI does not establish that evidence.
