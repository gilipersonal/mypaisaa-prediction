ARC-01

Source rights and full-budget feasibility

Yahoo Finance + Twelve Data Grow preferred candidates; Basic/Free for dev alongside synthetic fixtures. Verify each listing/use, rights and cost. Basic currently has 8 credits/minute and 800 weighted credits/day, reset 00:00 UTC.

ARC-02

Ledger, imports and write ownership

DynamoDB + private encrypted S3, with one controlled backend service for owner-confirmed financial ledger changes.

ARC-03

Durable workflow orchestration

Python Lambda Durable Functions is primary. FastAPI runs on ordinary API Lambdas. No Step Functions in the initial direction; SQS buffers work and EventBridge Scheduler supplies clocks.

ARC-04

ML training and serving execution

Capped on-demand SageMaker CPU training/evaluation; approved portable S3 artefacts used for Lambda inference where compatible; store daily forecasts. No always-on endpoint by default.

ARC-05

Forecast experiments, probability calibration and recommendations

Baselines first, then bounded challengers. Additional news, pattern, analog/event and LLM-derived factors must demonstrate incremental value. All agreed horizons/capabilities remain.

ARC-06

Anthropic route, memory, cache and batch boundaries

Separate Lambda workers per Claude task route with distinct permissions/context/tools/budgets/evals, sharing one versioned bounded Anthropic client-SDK runner. Claude runs on Anthropic.

ARC-07

Identity, session recovery and action-bound step-up

Server-verified Cognito authentication assurance/freshness for sensitive actions, with verified fresh-sign-in fallback meeting the same action policy. Bind approvals to owner, environment, exact action/payload/version and expiry.

ARC-08

Admin scope, audit integrity, retention and recovery

Specify all identified admin domains now; design their complete journeys after architecture agreement and before the first application build. Implementation may be phased.

ARC-09

Guardrails and evaluation harness

Inspect AI + typed MP-specific deterministic checks for agent evaluation. Runtime guards, pytest and numerical forecast validation retain distinct roles.

ARC-10

Client rendering and shared contracts

Static interactive SvelteKit PWA shell/assets on S3/CloudFront with authenticated FastAPI. No separate SvelteKit SSR runtime selected; Swift/SwiftUI within the RN shell remains.

ARC-11

Environment isolation, region, compatibility and whole-system recost

Separate dev/prod AWS workload accounts under consolidated billing. One aggregate £100/month all-in envelope: £70 operation + £30 reserve; no multiplication of free tiers or provider credits.

ARC-12

Architecture and phase-document freeze

Central architecture-area specifications and shared decisions/contracts linked to one page per MP phase and individual source/contract/acceptance-test/UX-traced Jira stories.

Story readiness contract

Every implementation story needs an actual Jira key and local stable ID; parent/phase; user outcome; sources and MP-specific adaptation; precise positive/negative acceptance; producer/consumer contracts; units and error semantics; code ownership; data/privacy/authority boundaries; UX states/platforms; test fixtures and expected results; failure/recovery; telemetry/audit/cost events; dependencies; estimate/uncertainty; rollback and release evidence. Port work is explicit when shared contracts cannot supply the client implementation.

Use four readiness states: draft, blocked on architecture, blocked on UX, and ready for an explicitly authorised build. Current implementation stories are draft/blocked. A checklist is not automatically satisfied when a ticket is created.

Each MA concept receives an explicit disposition: retained, adapted, rejected/superseded, reference-only or out of scope. Preserve the original source reference while writing MP acceptance in MP terms. The source-to-phase crosswalk alone does not complete sentence-level acceptance decomposition.
