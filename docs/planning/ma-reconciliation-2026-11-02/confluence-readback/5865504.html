Story catalogue and planned acceptance

6 current local story drafts. An actual Jira implementation story and detailed readiness evidence are required before UX; the closure tickets above are planning work, not substitutes.

L2-S01 · Cognito identity and owner recovery

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Specify managed Apple/Google/passkey sign-in and server-verified account linking; email similarity alone cannot merge identities.

  • Define two independent passkey paths, verified provider links, lost-device/recovery proof, session revocation and sensitive-action reauthentication.

  • Demonstrate denied cross-environment/cross-owner access and audit recovery/link changes without exposing identity tokens.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: Threat model and auth contracts; recovery/linking negative scenarios; eventual web/native integration results.

L2-S02 · Private durable storage and job contracts

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Specify isolated dev/prod identities and encrypted storage with least privilege; synthetic dev cannot write production.

  • Specify conditional ledger/audit/outbox writes and S3 hash/manifest publication boundaries; uploaded bytes and database pointers are not one transaction.

  • Retries use idempotency keys, bounded backoff and quarantine; no duplicate financial side effect after timeout/replay.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: Access-pattern model; write-failure matrix; planned idempotency/fault-injection cases.

L2-S03 · Launch dashboard cost meter and reconciliation

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Main dashboard shows dev/prod/local API/shared-unallocated costs with provider/agent/model/feature/service drill-down and source age.

  • Separate live estimates from delayed billing and gross usage from credit applied/cash; Anthropic billing collection every 6 hours, AWS daily, bounded and cached.

  • Unknown shared credit stays unknown and is never multiplied per environment; show collector failures and reconciliation discrepancies.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: Cost event and allocation schemas; dashboard states; stale/unknown/adjusted-bill synthetic cases.

L2-S04 · Enforce discretionary spending admission

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Evaluate forecast monthly cash against £60 warning/£75 reduced optional work/£85 pause-new-optional-paid thresholds while retaining £100 total ceiling and £70+£30 plan.

  • Use bounded reservations/limits for concurrent jobs; refuse uncovered or unverifiable Claude calls and pause optional calls at agreed low-credit conditions without paid fallback.

  • Show uncertainty from delayed AWS billing; approval thresholds are not claimed to provide an instantaneous universal AWS shutoff. Keep deterministic essential views available.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: Admission state table; concurrent-reservation and unknown-credit cases; full-workload stress budget.

L2-S05 · Authenticated API and resumable SSE

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Version authenticated APIs and short-lived heartbeat-enabled SSE; use durable event IDs/cursor recovery where supported, refetch durable records after gaps.

  • Define reconnect/token-expiry/ordering/dedup/backpressure and multi-tab/background rules; no secrets or durable financial truth solely in a stream.

  • Cost active connections and validate selected API/Lambda streaming compatibility before implementation; starter unauthenticated volatile SSE is not production evidence.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: API/event examples; disconnect/expired-session cases; streaming compatibility and cost evidence.

L2-S06 · Telemetry, evidence separation and original archive

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Plan logs 14 days, rich traces 30, run summaries 90 subject to measured cost; maintain distinct durable financial/forecast/approval/source audit lifecycles.

  • Plan encrypted private S3 originals with renewable 24-month retention and owner extension/deletion controls; define versions/derivatives/backups and no automatic expiry deletion yet.

  • Redact document contents, holdings, tokens and prompts from operational telemetry; correlation IDs link to access-controlled evidence.

Contracts: IdentitySession, SensitiveAction, ApprovalRequest, JobRecord, OutboxEvent, RunRecord, CostReservation. Evidence/examples: Record-class retention table; redaction cases; source-to-ledger/model audit examples.

UX states to specify after architecture sign-off

  • Success, empty, loading, partial and unavailable; stale source and insufficient evidence.

  • Permission denied, fresh authentication required, approval pending/expired/rejected and conflicting revision.

  • Offline/reconnecting, delayed job, retry exhausted, partial commit and safe recovery.

  • Privacy mode, keyboard/screen reader, light/dark and reduced-motion equivalents on web and Apple.

Audit, monitoring and cost acceptance

  • Record relevant actor/environment/business IDs, source/config/model versions and immutable approval/change/run evidence.

  • Define signals for failure, lateness, duplicate handling, source age and reconciliation; redact private payloads from operational telemetry.

  • Include source/provider, compute, storage, trace, retry and eval costs in the shared budget; no silent paid fallback.

Exit demonstration and failures

Foundation safeguards and cost attribution must precede paid jobs, real documents and external activation.

The planned exit demonstration must run the phase user journey plus one permission failure, one stale/partial data case, one duplicate/reconnect/retry case and one recovery path with evidence. Scientific phases additionally prove temporal/data maturity invariants; no invented live accuracy.

Failure/recovery intent: Fail closed for unknown paid-call coverage; stop optional work; retain durable state and deterministic reads.

No exit is currently certified. Deployment, live activation, model eligibility and owner approval are separate records.
