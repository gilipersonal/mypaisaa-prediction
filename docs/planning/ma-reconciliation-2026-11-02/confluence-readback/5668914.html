L3-S01 · Instrument identity, entitlement and cadence

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Support initial UK/US/India 20–30 real-ID synthetic instruments, preserving issuer/security/listing/venue, GBP/GBX/local currencies and NAV versus OHLC semantics.

  • Before live activation, resolve owner identities and source rights/history/latency/storage for Yahoo plus exact Twelve Data Grow tier; then propose the balanced research watchlist for owner approval.

  • Record source capability by listing; 30-minute risk/quote refresh only where supported, otherwise daily labelled analysis and suppressed unsupported intraday alerts; no paid provider addition without approval.

Contracts: SourceCapability, MarketObservation, FXObservation, PerformanceResult, ExposureSnapshot, BenchmarkComparison. Evidence/examples: Listing/capability matrix; entitlement evidence before live; ambiguous/dual-listing/GBX/NAV cases.

L3-S02 · Point-in-time ingestion and data health

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Pin source publication/observation/ingestion/known-at times, corporate actions, FX/calendar versions and quality flags.

  • Backfill toward ten years or inception where entitled; gaps/revisions/partial exposure history remain explicit and cannot be replaced by current constituents.

  • Handle provider disagreement, missing bars, market holidays/half-days/DST, quota failures and safe daily fallback with provenance.

Contracts: SourceCapability, MarketObservation, FXObservation, PerformanceResult, ExposureSnapshot, BenchmarkComparison. Evidence/examples: Provider contract fixtures; ingestion/revision/gap cases; per-market coverage report.

L3-S03 · Ledger performance, XIRR and benchmarks

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Consume approved L1 ledger/read/sufficiency contracts; compute XIRR and holdings only where required cash flows and prices exist, otherwise show supported partial analysis.

  • Specify GBP overview/local detail, FX date, fees/income/corporate-action and return conventions; choose holding, blended-portfolio and global equity benchmarks.

  • Use decimal money and independent known-answer reconciliation cases; never infer transactions from a holdings snapshot to manufacture XIRR.

Contracts: SourceCapability, MarketObservation, FXObservation, PerformanceResult, ExposureSnapshot, BenchmarkComparison. Evidence/examples: L1 contract join cases; financial golden fixtures; benchmark methodology approval.

L3-S04 · Portfolio exposure and risk facts

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.

  • Compute exposure/overlap/HHI/currency and scenario facts only from dated evidence; label provisional proxy or missing holdings exposure.

Contracts: SourceCapability, MarketObservation, FXObservation, PerformanceResult, ExposureSnapshot, BenchmarkComparison. Evidence/examples: Risk formula/window decision; concentration/loss golden fixtures; incomplete-cost/exposure cases.

L3-S05 · Daily and market-aware refresh orchestration

State: umbrella_requires_decomposition; actual implementation Jira key not allocated. Dependencies: see phase gates.
