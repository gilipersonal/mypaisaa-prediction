MA-27 · The household's records live in one dynamic structure: kinds as data, records as documents, history as events, figures as views

Original source description, including acceptance criteria: historical reference; newer MP decisions take precedence.

As the developer I want the household's records kept in one dynamic structure so that a new kind of asset, debt or account needs no new table and no migration.

Where. src/mypaisa_agent/registry/; ARCHITECTURE.md 4.

Keys built for the questions the household will ask (Arun, 24 Oct 2026: "I will be making such queries in future about my transactions and investments"). One table, every item under the household; records, events and views are each keyed so that every question below is a single Query, never a Scan. The questions are:

  • last month's transactions for the household;
  • my transactions this year;
  • every transaction on one holding or loan;
  • dividends or fees in a date range;
  • a holding's valuation history;
  • the changes one member made.

Dates are ISO, so key order is date order.

Acceptance.

  • Kinds are data: each kind is a versioned spec, and a record names its kind and version.
  • Records are documents: each record carries its kind, version, owners with their shares, country, currency, liquidity, status, parent, instrument and attributes, keyed by the household (ARCHITECTURE.md 4).
  • History is events: every change, a correction made in place included, is appended as an event with who and when; nothing is overwritten.
  • Figures are views: every figure is a view rebuilt from the events, and a test rebuilds each view from scratch and gets the same figures.
  • No migration for a new kind: adding a kind's spec is enough, with no new table and no code change to the store (test).
  • A repository function serves each question above, and a test proves each one is a single Query with the right key condition. A test fails if the registry layer ever calls Scan.
  • ARCHITECTURE.md §4 records the structure. A seed command loads the first record.
  • Gates: ruff, pyright, pytest.

Depends on.

  • MA-24
  • MA-26

Updated 26 Oct 2026 (MA-186): the fixed entities and their key table give way to one dynamic structure: kinds as data, records as documents, history as events, figures as views.

Stack (MA-265). The registry is a thin typed single-table repository in src/mypaisa_agent/registry/ built directly on Pydantic v2 models (Kind, Record, Event, Commitment, PlanItem, View), boto3's dynamodb client and resource (TypeSerializer and TypeDeserializer with Decimal conversion at the wire boundary), and mypy-boto3-dynamodb (boto3-stubs[dynamodb]) under strict pyright.
