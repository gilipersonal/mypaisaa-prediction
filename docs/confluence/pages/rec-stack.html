🔀 How one question flows

The owner taps Why did this forecast fall? Every hop below is proposed; the step that crosses SQS still needs its propagation proved.

StepWhat happensWhat travels with it

1. The door

The PWA or the Apple app sends the question to POST /api/v1/conversations/{id}/turns with the Cognito token

A new W3C traceparent and a client_message_id, which doubles as the idempotency key

2. API Gateway

Checks the token, then hands the request to the API Lambda

Its own request_id

3. FastAPI

Pydantic validates the body. The cost check reserves the turn's maximum spend. A run record is written as accepted, and the job goes to the chat route worker

Returns 202 with the job id, request_id and trace_id

4. Chat route worker

Marks the run started and calls Sonnet 5.5 in a server-controlled loop. Each tool call reads stored forecasts, prices and event analyses from DynamoDB

run_id on every log line and span; no prompt text

5. The answer

Every figure in it comes from a tool result. The turn is stored append-only with its citations, and the run record closes with tokens, cost, tools and outcome

Model id, token counts, cost estimate

6. Back to the door

An SSE notice says the turn is ready; the door re-reads it with an authenticated GET

The notice holds an event id, a type, a time and a resource reference, nothing more

📜 The contracts every layer keeps

  • One error shape on every failure, 401, 403, 422 and 500 alike: a code, a plain message, the request_id and the trace_id. Proposed.

  • Client types come from the API. FastAPI's OpenAPI document generates the TypeScript types for the web and the Swift types for the app, so a field renamed on the server breaks a build, not a screen. Proposed.

  • SSE stays thin: one-way, heartbeats, resume from the last event id where it can, and never holdings, credentials, provider payloads or model artefacts.

  • Every command is idempotent. The same key twice gives the same result and one ledger change.

  • Money is a decimal, never a float, from the Pydantic model to the DynamoDB number. Proposed.

  • Every market observation keeps its provider, symbol mapping, source time, ingestion time and quality flags, and is validated before it is stored.

  • Every prediction carries its as-of time, target, horizon, distribution or probability, calibration, model version, data cutoff and explanation references.

Where this differs from the sister project

  • No UI kit, chart library or framework version is pinned before the UX work; the sister project pinned them all.

  • Swift keeps the Apple app's offline cache, as AGENTS.md says; the React Native shell does not.

  • Long work runs in Lambda Durable Functions (ARC-03), not Step Functions.

  • The ledger has one controlled writer and append-only predictions; no hash-chained audit claim is carried over until it is proved.

  • One Lambda adapter for both the API and the stream is proposed, so the code path is the same on a laptop and on AWS.
