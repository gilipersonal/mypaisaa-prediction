🏷️ One ID scheme for web and Apple

One dictionary of test IDs, kept with the shared contracts, generates both sides: data-testid for the SvelteKit PWA, which Playwright finds with getByTestId, and Swift constants for .accessibilityIdentifier and the shell's testID, which Maestro finds with its id selector. One journey then reads the same on both doors.

  • IDs name the job, not the look: mpp.forecast.freshness, mpp.import.approve.

  • IDs never carry a value, a holding or anything personal.

  • A check fails when a Maestro flow or a Playwright test names an ID the dictionary lacks.

  • An ID is for tests; VoiceOver reads the label. Tests check both, so an ID never stands in for a missing label.

  • The prefix mpp. is proposed so MP's IDs never mix with MA's mp. dictionary if the two ever exchange data (PH-09).

  • That the shell's testID reaches iOS as the accessibility identifier, through SwiftUI views hosted in the shell, is to be proved in the first bridge spike.
